# Story to Production handoff

Status: first documented integration step, 2026-09-17; no executable import contract. Story-side details live in `comic-framework-story/schemas/lettering-handoff.md`.

## Inputs and mapping

Supply the authoritative script/adaptation and revision, page/panel IDs, exact text units, speakers, narrative reading order, acceptance scope and unresolved questions. Production links these to its physical slot map. Story numbering, physical positions, layout document pages and printed folios are distinct.

Draft input may support a clearly marked layout probe. It does not become an accepted script because a CSV or page mockup exists. Preserve published source text and document any adapted version separately.

## What Production returns

Return layout pressure, proposed text changes, reading-order problems, source mismatches and impacts of ads/page turns with affected IDs and revisions. Production may adjust placement within authorized intent; it must not silently cut dialogue, change speakers or turn exposed facing-page information into a claimed hidden reveal.

## Correction loop

Record old/new wording and reason, resolve Story changes through the project's existing authority, synchronize the editable Story/adaptation source and lettering list, then update layout and check the exported result. Track local layout text changes before reimport. Layout-only wrapping does not create a new narrative revision.

Text acceptance, Design approval, plan acceptance and print release remain separate. See [Lettering and print workflow](../lettering-and-print-workflow.md) for the combined process and current implementation limits.
